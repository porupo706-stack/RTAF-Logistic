# ระบบจัดการคลังพัสดุ (Google Apps Script + Google Sheets)

ระบบบริหารคลังพัสดุที่ทำงานบน Google Sheets และ Google Apps Script ใช้งานผ่านเว็บ (มือถือ/คอมพิวเตอร์) ต้นแบบพัฒนาสำหรับ **คลังพัสดุ กองบิน ๗** และเขียนให้นำไปปรับใช้กับหน่วยงานอื่นได้โดยคงฟอร์มเดิม

## ความสามารถ

- ค้นหาพัสดุจากชื่อ/หมายเลข/เลขทะเบียน หรือสแกน QR Code ด้วยกล้อง
- รับพัสดุเข้าใหม่ (มีช่องหน่วยนับ ที่เก็บ จำนวน และวันที่ผลิต/เลขทะเบียนรถสำหรับสายขนส่ง)
- ปรับยอดรับ-จ่าย พร้อมบันทึกประวัติรับจ่ายและยอดคงเหลืออัตโนมัติ
- แดชบอร์ด: จำนวนพัสดุทั้งหมด, รับ/จ่ายวันนี้, พัสดุใกล้หมด (≤ 5)
- รายงาน: พัสดุทั้งหมด, ใกล้หมด, ประวัติรับ-จ่าย, สรุปรายวัน, พิมพ์ป้าย QR Code
- **บันทึกเป็น Excel แบบ "บัญชีตรวจสอบพัสดุ (ผนวก ค)"** ทุกสายงาน (1 สายต่อ 1 ชีท) ไม่แสดงรายการที่ยอดเป็น 0 และมีช่องลงชื่อผู้ตรวจที่ท้ายกระดาษทุกหน้า
- สร้าง QR Code ของพัสดุแต่ละรายการให้ชี้กลับมาที่หน้าพัสดุนั้นในระบบ

## โครงสร้างโปรเจกต์

```
.
├── Code.gs       # ฝั่งเซิร์ฟเวอร์ (Apps Script): อ่าน/เขียนชีท, ประวัติรับจ่าย, สร้าง QR
├── Index.html    # ฝั่งหน้าเว็บ: UI, รายงาน, สร้างไฟล์ Excel (ExcelJS)
└── README.md
```

> ชื่อไฟล์ HTML ต้องเป็น `Index` เพราะ `Code.gs` เรียก `HtmlService.createTemplateFromFile('Index')`

## เครื่องมือและบริการภายนอกที่ใช้

เครื่องที่ใช้งานต้องออกอินเทอร์เน็ตไปยังบริการเหล่านี้ได้

| บริการ | ใช้ทำอะไร |
|---|---|
| quickchart.io | สร้างภาพ QR Code |

# ขั้นตอนการติดตั้ง (ตั้งแต่ต้นจนจบ)

## ขั้นที่ 1 สร้าง Google Sheet

สร้างสเปรดชีตใหม่ (หรือคัดลอกไฟล์ต้นแบบ) แล้วสร้างชีทชื่อตามนี้ **ให้ตรงตัวอักษร**

| ชีท | หน้าที่ |
|---|---|
| `สายพลา` | คลังพัสดุสายพลาธิการ |
| `สายสื่อสาร` | คลังพัสดุสายสื่อสาร |
| `สายช่างโยธา` | คลังพัสดุสายช่างโยธา |
| `สายขนส่ง` | คลังพัสดุสายขนส่ง (มีวันที่ผลิตและเลขทะเบียนรถเพิ่ม) |
| `ประวัติรับจ่าย` | บันทึกการรับ-จ่ายทุกครั้ง |
| `สรุปรายวัน` | สรุปยอดรับ/จ่าย/คงเหลือรายวัน |

### โครงคอลัมน์ของชีทสายงาน (4 ชีทแรก)

แถว 1 เป็นชื่อหัวเรื่อง แถว 2 เป็นหัวตาราง ข้อมูลเริ่มที่แถว 3

| คอลัมน์ | หัวตาราง (ต้องตรงกับข้อความนี้) | หมายเหตุ |
|---|---|---|
| A | ลำดับ | ระบบเติมให้เมื่อรับพัสดุใหม่ |
| B | หมายเลขพัสดุ | ตั้งรูปแบบเป็น Plain text เช่น `7530-35-710-2993` |
| C | ชื่อพัสดุ | |
| D | หน่วยนับ | เช่น EA, SH, PR, เครื่อง, ผืน (ว่างได้) |
| E | ที่เก็บพัสดุ | |
| F | จำนวนคงเหลือ | ตัวเลข |
| G | คิวอาร์โค้ด | ระบบสร้างสูตร `=IMAGE(...)` ให้ |
| H, I | (เฉพาะ `สายขนส่ง`) วันที่ผลิต, เลขทะเบียนรถ | ต้องอยู่ถัดจากคอลัมน์ QR ไปทางขวา 1 และ 2 ช่อง |

ระบบหาคอลัมน์จาก **ข้อความหัวตาราง** ในฟังก์ชัน `detectCols_()` (ค้นใน 3 แถวแรก) จึงสลับลำดับคอลัมน์ได้ตราบที่หัวตารางยังมีคำว่า `หมายเลข`, `ชื่อพัสดุ`, `หน่วยนับ`, `ที่เก็บ`, `คงเหลือ`, `คิวอาร์`/`QR` ถ้าไม่พบหัวตาราง ระบบใช้ตำแหน่งสำรอง (B=หมายเลข, C=ชื่อ, D หรือ E=ที่เก็บ ฯลฯ)

### โครงคอลัมน์ของชีท `ประวัติรับจ่าย`

แถว 1-2 เป็นหัวเรื่อง/หัวตาราง ข้อมูลเริ่มแถว 3

| A | B | C | D | E | F | G | H |
|---|---|---|---|---|---|---|---|
| ลำดับ | วันที่รับ | วันที่จ่าย | ประเภท (รับเข้า/จ่ายออก/แก้ไขข้อมูล) | ชื่อพัสดุ | หน่วยงานที่รับ/จ่าย | จำนวน | ยอดคงเหลือ |

### โครงคอลัมน์ของชีท `สรุปรายวัน`

| A | B | C | D | E |
|---|---|---|---|---|
| วันที่ (dd/MM/yyyy) | ชื่อพัสดุ | รับ | จ่าย | คงเหลือ |

## ขั้นที่ 2 สร้างโปรเจกต์ Apps Script

1. เปิดสเปรดชีตแล้วไปที่ **ส่วนขยาย → Apps Script** (โปรเจกต์ต้องผูกกับสเปรดชีตนี้ เพราะโค้ดใช้ `getActiveSpreadsheet()`)
2. ลบโค้ดเริ่มต้น แล้ววางเนื้อหา `Code.gs` ลงในไฟล์ `Code.gs`
3. กด **+ → HTML** ตั้งชื่อ `Index` แล้ววางเนื้อหา `Index.html`
4. กดบันทึก

## ขั้นที่ 3 Deploy เป็น Web app เพื่อรับ URL

1. กด **Deploy → New deployment → Select type → Web app**
2. ตั้งค่า
   - **Execute as**: Me (เจ้าของสเปรดชีต)
   - **Who has access**: เลือกให้เหมาะกับหน่วย (เช่น เฉพาะบัญชีในองค์กร) ผู้ที่เข้าถึงได้จะแก้ข้อมูลในชีทผ่านระบบได้
3. กด **Deploy** อนุมัติสิทธิ์ แล้วคัดลอก URL ที่ลงท้ายด้วย `/exec` เก็บไว้ (เรียกว่า `WEB_APP_URL`)

## ขั้นที่ 4 แก้ค่าที่ผูกกับหน่วยงาน

> **วิธีหาจุดที่ต้องแก้เร็วที่สุด:** ในตัวแก้ไข Apps Script กด Ctrl+F แล้วค้นหา `[CHANGE]` ทั้งใน `Code.gs` และ `Index.html` โค้ดใน repo นี้ใส่ป้ายกำกับไว้ทุกจุดแล้ว
> - `[CHANGE]` = ต้องแก้ทุกหน่วยงาน
> - `[CHANGE-ถ้า...]` = แก้เฉพาะเมื่อหน่วยงานของคุณต่างจากต้นแบบ
>
> URL และโลโก้ใน repo เป็นค่าจำลอง ต้องแทนด้วยของจริงก่อนใช้งาน
> - `https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec` → ใส่ Web app URL ของคุณ (รวม 4 จุด: `Code.gs` 3 จุดในฟังก์ชัน `openFullScreen`, `addNewItem`, `rebuildAllQRCodes` และ `Index.html` 1 จุดที่ตัวแปร `QR_SCRIPT_URL`)
> - `https://YOUR-DOMAIN/path/to/logo.png` → ใส่ลิงก์โลโก้ของหน่วยงาน

ใส่ `WEB_APP_URL` และชื่อหน่วยในจุดต่อไปนี้ แล้ว Deploy เวอร์ชันใหม่อีกครั้ง

## ขั้นที่ 5 กรณีหน่วยงานมีสายงานต่างจากต้นแบบ

ชื่อสายถูกอ้างอิงหลายที่ ต้องแก้ให้ตรงกันทั้งหมด

**`Code.gs`**
- ตัวแปร `sheetNames` / `invSheets` ในฟังก์ชัน `getItemData`, `getDashboardData`, `getTotalItemsList`, `getHistoryByDate`, `fixHistoryBalance`, `fixAllHistoryBalance`, `getDailySummaryByRange`, `getHistoryByRange`, `generateDailySummary`, `rebuildAllQRCodes`, `fixColumnBFormat`, `getAnnexItems`
- เงื่อนไข `isTargetSheet` ใน `searchParcelByName`

**`Index.html`**
- ตัวเลือก `<option>` ในฟอร์มรับพัสดุเข้าใหม่
- แท็บใน `openTotalItems` / `openLowStock` (`switchTotalTab`, `switchLSTab`)
- ปุ่มเลือกสายและรายการ `['all', ...]` ใน `openReportSheet`, `_selectSheet`, `_selectRpt`
- `ANNEX_LINES` (ข้อ 4.3)

ชื่อ `สายขนส่ง` ผูกกับช่อง "วันที่ผลิต" และ "เลขทะเบียนรถ" ถ้าหน่วยใหม่ไม่มีสายนี้ให้ปล่อยไว้ได้ ถ้ามีสายอื่นที่ต้องใช้ช่องแบบนี้ ให้เพิ่มเงื่อนไขในจุดที่เช็ก `'สายขนส่ง'` ทั้งใน `Code.gs` และ `Index.html`

## ขั้นที่ 6 นำเข้าข้อมูลพัสดุ

1. กรอกข้อมูลลงชีทสายงาน (หมายเลข ชื่อ หน่วยนับ ที่เก็บ จำนวน) หรือใช้หน้า "รับพัสดุเข้าใหม่" ในระบบ
2. ถ้าหมายเลขพัสดุถูกแปลงเป็นตัวเลข รัน `fixColumnBFormat()` เพื่อจัดรูปแบบเป็นข้อความแบบมีขีด (รองรับความยาว 11-13 หลัก) ฟังก์ชันนี้จะเรียก `rebuildAllQRCodes()` ให้ด้วย

## ขั้นที่ 7 สร้าง QR Code และตั้ง Trigger

รันจากตัวแก้ไข Apps Script (เลือกฟังก์ชันแล้วกด Run)

| ฟังก์ชัน | ทำอะไร | เมื่อไหร่ |
|---|---|---|
| `rebuildAllQRCodes()` | สร้างสูตร QR ทุกแถวใหม่ให้ชี้ `WEB_APP_URL` | หลังแก้ URL หรือหลังเพิ่ม/ย้ายคอลัมน์ |
| `installOnEditTrigger()` | ติดตั้ง trigger ให้ยอดคงเหลือในชีทประวัติอัปเดตเมื่อมีการแก้ไข | ครั้งเดียวต่อโปรเจกต์ |

ครั้งแรกที่รัน Google จะขอสิทธิ์เข้าถึงสเปรดชีตและการเชื่อมต่อภายนอก ให้อนุมัติ

## ขั้นที่ 8 ทดสอบก่อนใช้งานจริง

- [ ] เปิด URL `/exec` แล้วหน้าเว็บขึ้นพร้อมชื่อหน่วยและโลโก้ถูกต้อง
- [ ] ค้นหาพัสดุได้ และสแกน/เปิดลิงก์ `?id=หมายเลขพัสดุ` แล้วเจอรายการนั้น
- [ ] รับพัสดุใหม่: ข้อมูลลงชีทถูกคอลัมน์ (รวมหน่วยนับ) และมีบรรทัดใหม่ใน `ประวัติรับจ่าย`
- [ ] ปรับยอดรับ/จ่าย: ยอดในชีทเปลี่ยนและประวัติบันทึกถูกต้อง
- [ ] รายงานพัสดุทั้งหมด → เลือก "บัญชีตรวจสอบพัสดุ (ผนวก ค)" → บันทึกเป็น Excel
  - ได้ไฟล์ชีทครบทุกสาย ไม่มีรายการยอด 0
  - เปิด Print Preview แล้วมีช่องลงชื่อท้ายทุกหน้า
- [ ] พิมพ์ป้าย QR แล้วสแกนเจอพัสดุถูกรายการ

## ขั้นที่ 9 เผยแพร่ให้ผู้ใช้

1. ส่งลิงก์ `/exec` ให้ผู้ใช้ (หรือทำเป็น QR/บุ๊กมาร์กบนมือถือ)
2. ทุกครั้งที่แก้โค้ด ต้องไปที่ **Deploy → Manage deployments → Edit → Version: New version** แล้ว Deploy ไม่เช่นนั้นหน้าเว็บยังเรียกโค้ดเวอร์ชันเก่า

# การทำงานของรายงานผนวก ค

- ปุ่ม **บันทึกเป็น Excel** อ่านข้อมูลสดจากชีทผ่าน `getAnnexItems()` แล้วสร้างไฟล์ในเบราว์เซอร์ด้วย ExcelJS
- เลือก "ทั้งหมด" จะได้ครบทุกสายใน `ANNEX_LINES` เลือกสายเดียวจะได้ชีทเดียว
- ชื่อไฟล์: `คงคลัง ทุกสาย <ปี พ.ศ. 2 หลัก>.xlsx` หรือ `คงคลัง สาย... <ปี>.xlsx`
- คอลัมน์ในไฟล์: ลำดับ, หมายเลขพัสดุ, ชื่อพัสดุ, หน่วยนับ, จำนวนตามบัญชี, จำนวนนับได้, ขาด, เกิน, หมายเหตุ ค่า "จำนวนนับได้" ตั้งต้นเท่ากับจำนวนตามบัญชี ขาด/เกินเป็น "-" แก้ในไฟล์ได้
- ไฟล์ Excel เป็นสำเนา ค่าที่แก้ในไฟล์ไม่ย้อนกลับเข้าระบบ และการกด export ใหม่จะได้ไฟล์ใหม่
- หน่วยนับดึงจากคอลัมน์ "หน่วยนับ" ในชีท ถ้าไม่มีคอลัมน์หรือช่องว่าง จะเว้นว่างไว้

# ข้อควรระวังเมื่อเผยแพร่เป็น repo บน GitHub

- **อย่า commit URL การ deploy จริง, ลิงก์ภายในองค์กร หรือข้อมูลพัสดุ** ใน repo สาธารณะ โค้ดใน repo นี้ใช้ค่าจำลอง `YOUR_DEPLOYMENT_ID` และ `YOUR-DOMAIN` ไว้แล้ว ให้แก้เป็นค่าจริงเฉพาะในโปรเจกต์ Apps Script ของคุณ แล้วอย่านำกลับมา commit
- ลิงก์โลโก้ควรเป็นไฟล์ที่หน่วยงานของคุณมีสิทธิ์ใช้งานและเข้าถึงได้เสมอ
- ถ้าต้องการ sync โค้ดกับ GitHub ใช้ [clasp](https://github.com/google/clasp) (`clasp clone` / `clasp push`) และเพิ่มไฟล์ `appsscript.json` เข้า repo ด้วย

# การแก้ปัญหาเบื้องต้น

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| สแกน QR แล้วไปหน้าของหน่วยอื่น | ยังใช้ URL เดิมใน `scriptUrl` / `QR_SCRIPT_URL` | แก้ตามข้อ 4.1 แล้วรัน `rebuildAllQRCodes()` |
| ค้นหา/รายงานไม่เจอข้อมูลของสายหนึ่ง | ชื่อชีทไม่ตรงกับในโค้ด | ตรวจชื่อชีทและตัวแปร `sheetNames` / `invSheets` |
| จำนวนหรือที่เก็บไปโผล่ผิดช่อง | หัวตารางไม่ตรงข้อความที่ระบบหา | ใช้หัวตารางตามขั้นที่ 1 |
| แก้โค้ดแล้วหน้าเว็บไม่เปลี่ยน | ยังไม่ได้ Deploy เวอร์ชันใหม่ | ขั้นที่ 9 ข้อ 2 |
| กดบันทึก Excel แล้วไม่มีไฟล์/ค้าง | เบราว์เซอร์บล็อกการดาวน์โหลด หรือโหลด ExcelJS ไม่ได้ | ตรวจอินเทอร์เน็ตและการอนุญาตดาวน์โหลดของเบราว์เซอร์ |
| QR ในชีทไม่ขึ้นรูป | เครือข่ายเข้า quickchart.io ไม่ได้ | ตรวจการเชื่อมต่อ หรือเปลี่ยนผู้ให้บริการ QR ในสูตร `IMAGE` |
| ยอดคงเหลือในประวัติไม่ตรง | ยังไม่ได้ติดตั้ง trigger | รัน `installOnEditTrigger()` และ `fixAllHistoryBalance()` |
